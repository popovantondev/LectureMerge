# Правила проекта LectureMerge

Основная папка проекта — эта `lecture_merge`. Владелец требует сохранять
старые рабочие выпуски и делать доработки отдельными релизами.

1. Перед изменениями читать README.md, docs/VERSIONING.md и git status.
   Сохранять чужие незакоммиченные изменения.
2. Функциональные изменения вести в отдельной ветке; для больших изменений
   использовать отдельный worktree. Исходники и старые приложения в прежней
   папке «Оля лекции транскрипция FFMPEG» больше не редактировать.
3. Не изменять, не удалять и не перезаписывать releases/v*/ и dist/v*/.
   Не переносить существующие теги, не делать force push или reset --hard.
   Пробные сборки — bash Scripts/build.sh --preview, каждый раз новый каталог.
4. Новый выпуск получает новую VERSION и BUILD_NUMBER, запись в CHANGELOG.md,
   проверки по docs/BUILD.md, коммит и новый тег через Scripts/release.py.
   Документационные изменения без изменения приложения не требуют выпуска.
5. Перед релизом проверять структуру, относящиеся к изменению интеграционные
   сценарии, подпись .app, архивы и отказ перезаписи старой версии.
   Не приписывать локальным тестам проверку Android/Telegram или GitHub CI.
6. Не менять программу озвучки, пользовательские лекции, WAV/M4A/SRT,
   существующие проекты и ярлыки Dock при переносе/выпуске приложения.
7. Медиа, кэши, бинарные зависимости и ZIP исключены из Git.
   Релиз исходников формируется git archive; приложение архивируется отдельно.
8. Публикация на GitHub, создание remote и назначение лицензии требуют
   отдельного запроса владельца. Организация локального проекта не является
   таким запросом. Локальная история и теги разрешены текущей задачей.
