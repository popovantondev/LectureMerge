# Локальный Git и будущая публикация

Репозиторий пока локальный. Подготовлены README, CHANGELOG, .gitignore,
шаблоны ошибок/pull request и GitHub Actions. Remote не подключён,
исходники и приложение на сервер не отправлялись.

Workflow `.github/workflows/check.yml` проверяет структуру и Swift на macOS.
Он не скачивает лекции, не запускает аппаратные тесты, не публикует релизы
и не получает права записи. Его команда выполняется локально через check.sh;
сам GitHub Actions можно проверить только после отдельной публикации.

Настройка основана на [официальном actions/checkout](https://github.com/actions/checkout)
и [документации macOS runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

При будущем запросе владельца на публикацию:

1. Выбрать репозиторий, видимость и лицензию собственного кода.
2. Проверить состав `git ls-files` и описание сторонних компонентов.
3. Подключить remote и отправить исходники с нужным тегом.
4. Создать GitHub Release для этого же тега и приложить локальные ZIP,
   manifest.json и SHA256SUMS из releases/vX.Y.Z.

История Git не должна содержать готовые `.app`, исходные лекции, проекты
пользователя, кэши и крупные архивы зависимостей.
