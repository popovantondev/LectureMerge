# Подготовка GitHub

## Текущее состояние

- Выпуск 2.1.0 остаётся предыдущей неизменяемой версией. Выпуск 2.2.0 с
  локализацией RU/DE/EN опубликован в `popovantondev/LectureMerge`.
- Для подготовки выбран стиль аккаунта `popovantondev`: предполагаемое имя
  репозитория — `LectureMerge`; создан публичный репозиторий
  https://github.com/popovantondev/LectureMerge.
- В `.github/` уже есть шаблоны ошибок и pull request, а также GitHub Actions
  для проверки структуры и Swift на macOS.
- Workflow имеет `contents: read`, отключает сохранение credentials и не
  публикует релизы или пользовательские файлы. Он ещё не запускался на GitHub.
- `.gitignore` исключает `build/`, `dist/`, `releases/`, `.app`, ZIP, локальные
  медиа/субтитры, проекты и журналы. В `git ls-files` нет готовых приложений,
  релизных ZIP или медиафайлов; сторонние компоненты представлены лицензиями,
  уведомлениями и манифестом, без архивов FFmpeg.
- README приведён к формату других проектов аккаунта: краткое описание,
  ссылки на русский/немецкий/английский гиды, скачивание, быстрый старт,
  сборка, обратная связь, права и сторонние компоненты.
- Добавлен `RIGHTS.md` по модели TelegramMediaSender: исходники открыты для
  просмотра, лицензия на повторное использование не предоставляется; разрешено
  лично скачивать и запускать неизменённый релизный бинарник.
- `THIRD_PARTY.md` переименован в `THIRD_PARTY_NOTICES.md` для совпадения с
  остальными проектами.
- Для собственного кода лицензия по-прежнему не назначена и файл `LICENSE`
  намеренно не добавлен. Эту политику теперь объясняет `RIGHTS.md`.
- README и три пользовательских руководства доступны в репозитории по адресу
  `popovantondev/LectureMerge`; ссылка Releases 2.2.0 проверена.
- Предлагаемое краткое описание репозитория: `macOS app for combining lecture
  video, narration, and subtitles into MP4`.
- Предлагаемые topics: `macos`, `swift`, `apple-silicon`, `video`, `ffmpeg`,
  `subtitles`, `lecture-tools`. Их можно выставить при создании репозитория;
  локальные файлы Git не меняют эти настройки аккаунта.

Репозиторий и выпуск опубликованы. В релиз приложены приложение для Apple
Silicon, исходный архив, `manifest.json`, `SHA256SUMS` и `RELEASE.md`.
GitHub отображает контрольные суммы ZIP; страница релиза показывает тег
`v2.2.0`, коммит `19e6e9c` и метку Latest.

Workflow `.github/workflows/check.yml` проверяет структуру и Swift на macOS.
Он не скачивает лекции, не запускает аппаратные тесты, не публикует релизы
и не получает права записи. После публикации `Source checks` на `main`
завершился успешно; подробности приведены в
[`VERIFICATION-2.2.0.md`](VERIFICATION-2.2.0.md).

Настройка основана на [официальном actions/checkout](https://github.com/actions/checkout)
и [документации macOS runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

## Параметры публикации

- Владелец согласовал целевой адрес `popovantondev/LectureMerge` и публичную
  видимость. Для публикации подготовлен выпуск 2.2.0; 2.1.0 останется
  доступным в локальной истории.
- Публичная публикация выполнена по согласованному адресу. Не переписывать
  выпуски `v2.1.0` и `v2.2.0`.
- Видеоконвертер S03 ещё не реализован; он остаётся отдельной будущей задачей.

Для последующих обновлений:

1. Повторно проверить `git status` и состав `git ls-files`; сохранить только
   согласованные изменения и коммиты.
2. Использовать существующие адрес и публичную видимость репозитория.
3. Обновить локальные ссылки README и трёх языковых руководств при изменении
   адреса релиза.
4. Отправлять согласованные коммиты и новые теги через настроенный `origin`.
5. Проверить GitHub Actions после push. Этот CI выполняет только `check.sh`;
   аппаратное кодирование и тесты на реальных лекциях остаются локальными.
6. Создавать новый GitHub Release только после подготовки и локальной проверки
   соответствующей версии и её файлов.

История Git не должна содержать готовые `.app`, исходные лекции, проекты
пользователя, кэши и крупные архивы зависимостей.
