# Техническое задание: отдельная программа «Сборка лекций MP4»

Дата: 2 сентября 2026 года.

## 1. Назначение и состояние проекта

Нужно создать отдельное приложение для macOS с графическим интерфейсом. Оно собирает готовые лекции в MP4: видео, русская озвучка, оригинальный немецкий звук и два языка субтитров. При необходимости приложение уменьшает разрешение и перекодирует видео.

Это НЕ программа перевода или синтеза речи. Переводы и русская озвучка уже подготовлены другой программой. ChatGPT, Siri, платные API и токены для сборки MP4 не нужны.

Сейчас приложение только спроектировано. Реализованного нового GUI нет. Практически проверена команда FFmpeg из раздела 11.

Существующее приложение «SRT Озвучка» не изменять и не объединять с новым приложением. Новый проект должен жить отдельно. Рабочее название «Сборка лекций MP4» предложено ассистентом; окончательное название не утверждено.

## 2. Подтверждённый результат теста — важно сохранить

2 сентября 2026 года пользователь выполнил приведённую ниже команду FFmpeg и получил тестовый MP4 приблизительно на 30 секунд.

Пользователь сообщил: «сработало отлично через ffmpeg; моя девушка проверила на двух андроидах, а я на пк; все как надо».

Таким образом, вариант с русским звуком первым и по умолчанию практически прошёл проверку в Telegram на двух Android-смартфонах и ПК. Именно его использовать как основу реализации, а не снова начинать обсуждение формата MKV или предлагать удалить немецкую дорожку.

Оговорки:

- Это подтверждение для проверенных устройств, клиентов и способа отправки, а не гарантия для абсолютно всех версий Telegram.
- Точный способ отправки, модели Android и версии клиентов пользователь не указал. В инструкции ему предлагалась отправка как файла без сжатия.
- Пользователь подтвердил успешный результат в целом; отдельная проверка интерфейса переключения обеих дорожек субтитров не описана.

## 3. Компьютер пользователя

- MacBook Pro 14″, 2024, обычный Apple M4 — не M4 Pro и не M4 Max.
- 16 ГБ объединённой памяти, SSD 512 ГБ.
- macOS Sequoia 15.7.4 по предоставленному скриншоту.
- Интерфейс приложения и сообщения — на русском, для пользователя без опыта работы с FFmpeg.

## 4. Входные файлы и их подбор

Реальный пример папки:

`/path/to/lectures/Day_03`

Одна лекция состоит из блока файлов с общей основой имени:

```text
03_01_821049013_720p.mp4                 — видео с немецким звуком
03_01_821049013_720p.ru.siri.voice.wav   — готовая русская озвучка
03_01_821049013_720p.ru.srt              — русские субтитры
03_01_821049013_720p.srt                 — немецкие субтитры
```

В той же папке лежат аналогичные блоки следующих лекций. Также могут присутствовать `.ru.siri.voice.report.txt` и другие служебные файлы — их игнорировать.

Обязательные способы добавления:

1. Выбрать/перетащить видео и вручную указать русскую озвучку и два SRT.
2. Выбрать/перетащить несколько видео с автоматическим подбором соседних файлов.
3. Выбрать/перетащить папку и автоматически собрать очередь из найденных комплектов.

Входное видео: MP4 и MKV. Выход: MP4, без обязательного промежуточного MKV.

Основной вход русской озвучки — WAV. Полезно также поддержать M4A/AAC, поскольку отдельная программа озвучки впоследствии может перейти на AAC.

Правила подбора:

- Сопоставлять по полной общей основе имени и известным суффиксам, не просто по похожему номеру.
- Различать `.srt` и `.ru.srt`; не путать русский SRT с немецким.
- Не подхватывать промежуточные части перевода, отчёты и собственные результаты экспорта.
- При нескольких кандидатах русской озвучки не выбирать произвольно: показать неоднозначность и дать выбрать.
- Показать, какие именно файлы подобраны; разрешить замену любого из них вручную.
- Если отсутствует обязательный компонент, не выдавать комплект за полностью готовый.
- Если исходное видео содержит несколько аудиодорожек, дать выбрать немецкую; не считать любой первый поток гарантированно немецким.
- Поддержать пробелы, кириллицу и Unicode в путях. Не переименовывать исходники ради обработки.
- Подпапки можно добавить отдельным переключателем; автоматическая рекурсия не является подтверждённым требованием.

## 5. Обязательная структура итогового MP4

| Порядок | Содержимое | Язык и настройки |
|---|---|---|
| Видео | Исходный видеоряд или результат перекодирования | Корректные пропорции |
| Аудио № 1 | Русская озвучка | `rus`, первая среди аудио, `default` |
| Аудио № 2 | Немецкий звук исходного видео | `deu`, дополнительная, без `default` |
| Субтитры № 1 | Русский перевод | `rus`, предлагается `default`, как в успешном тесте |
| Субтитры № 2 | Немецкий оригинал | `deu`, без `default` |

Главный критерий пользователя: при открытии в Telegram на Android должен автоматически звучать русский язык. Русскую и немецкую речь не смешивать.

Немецкий звук брать прямо из исходного видео. Предварительное извлечение в отдельный временный файл не требуется. Порядок дорожек задавать явно через `-map`, а признаки основной дорожки — через `-disposition`.

Субтитры должны храниться ВНУТРИ MP4 отдельными переключаемыми дорожками, не быть постоянно нарисованными на изображении. SRT преобразовать в `mov_text`. Не обещать, что любой плеер, включая Telegram, предоставит управление обоими субтитрами.

Называть дорожки понятно: «Русский», «Deutsch — оригинал», «Русские субтитры», «Deutsche Untertitel».

## 6. Разрешение, качество и скорость

Пользователь явно запросил: 240p, 360p, 480p, 720p и 1080p. Для говорящих голов он будет выбирать 240p; для фитотерапии с текстом — 720p или 1080p.

Также нужен режим «Без перекодирования» для подходящих исходников: изменяются состав и настройки контейнера, видеоряд копируется без потерь.

Предлагаемые правила по умолчанию:

- Исходник 1080p или выше: предложить 720p.
- Исходник 720p: предложить 720p; если кодек совместим с целевым профилем и дополнительное сжатие не запрошено — копировать видео.
- Исходник ниже 720p: не увеличивать автоматически, предложить исходное разрешение.
- Выбор более высокого разрешения не должен молча выдавать увеличение картинки за улучшение качества. Апскейл по умолчанию выключен.
- Реальные параметры читать из файла, не доверять только надписи `720p` в имени.
- Сохранять пропорции, учитывать поворот и размеры пикселей; не обрезать кадр. Выходные размеры должны соответствовать требованиям кодека.
- Частоту кадров брать из оригинала, без произвольного ускорения/замедления видео.

Разрешение — не то же самое, что степень сжатия. Предложенный дополнительный выбор: «Компактно / Баланс / Чётче». Точные битрейты или параметры качества ещё не утверждены: подобрать на тестах говорящих голов и мелкого текста. Показывать приблизительный размер, не обещать точный заранее.

Базовый профиль совместимости:

- Контейнер MP4.
- Видео H.264, при перекодировании совместимый 8-битный формат 4:2:0.
- Русский звук AAC-LC. В прошедшем тесте: 128 кбит/с, 48 кГц, стерео.
- Немецкий AAC копировать без потерь, если он совместим. При неподходящем исходном кодеке потребуется преобразование в AAC с сохранением содержания.
- `-movflags +faststart` для удобного начала воспроизведения при загрузке.

Для скорости использовать аппаратное кодирование `h264_videotoolbox` на Apple Silicon. Это специализированный медиаблок M4, а не задача для Neural Engine. Наличие кодировщика в сборке FFmpeg уже проверено; реальную скорость и успешность аппаратного кодирования проверить при разработке. Показать понятную ошибку/вариант перехода на CPU при недоступности ускорения, не менять режим скрытно.

Опциональный CPU-режим для более тщательного сжатия можно добавить позже. HEVC и AI-улучшение изображения не нужны для первой версии.

## 7. Графический интерфейс и очередь

Предложенная технология: нативное окно macOS на Swift/AppKit или SwiftUI, FFmpeg для обработки, FFprobe для анализа. Это предложение реализации, а не уже написанная программа.

Пример структуры окна:

```text
[Добавить файлы]  [Добавить папку]

Лекция       RU звук   RU SRT   DE SRT   Результат   Статус
03_01        ✓         ✓        ✓        720p        Готова
03_02        ✓         ✓        ✓        240p        Готова
03_03        —         ✓        ✓        720p        Нет звука

Разрешение: [720p ▾]   Сжатие: [Баланс ▾]
[Применить ко всей очереди]

Сохранить: [Папка назначения ▾]

[Тест 30 секунд]          [Начать очередь]  [Остановить]
```

Нужно:

- Пакетная очередь и индивидуальные настройки каждого ролика.
- Общие настройки с кнопкой применения ко всей очереди.
- Показ реальных исходных разрешения, длительности, частоты кадров и кодека.
- Процент обработки файла, общая очередь, оценка оставшегося времени.
- Статусы: готов к запуску, отсутствуют файлы, неоднозначный подбор, обработка, завершён, ошибка, остановлен.
- Кнопка открытия результата в Finder.
- Кнопка короткого тестового MP4 до обработки всей лекции. Сначала начало на 30 секунд; выбор середины/фрагмента — полезное расширение.

Начать с одного одновременно обрабатываемого видео. Несколько файлов в очереди не требуют параллельного кодирования. Два одновременных задания добавлять только после замеров: пользователь хочет эффективное использование M4, а не максимальное число процессов любой ценой.

## 8. Сохранение и защита файлов

Обязательные принципы:

- Исходные видео, WAV и SRT никогда не перезаписываются и не удаляются автоматически.
- Итог создаётся под новым именем/в другой папке. Предложение: `Готовое` рядом с исходниками, с возможностью выбрать «Загрузки» или другую папку.
- Если итоговый файл уже существует: предложить «Пропустить / Сохранить копию / Заменить». Без явного согласия не перезаписывать.
- Даже при разрешённой замене сначала сформировать и проверить новый временный результат, затем заменить старый; не уничтожать рабочий результат в начале задания.
- Незавершённый файл не показывать как готовую лекцию.
- Проверять доступное место перед запуском, учитывая результат и временные данные.
- Служебные журналы сохранять отдельно от лекций, например в Application Support/Logs. Ранее пользователя раздражали отчёты рядом с аудио.
- Не очищать чужие файлы или исходники. Политику очистки только собственных временных данных реализовать явно и ограниченно.

Предложение по именам: `<идентификатор>_<фактическое-разрешение>.ru.mp4`, например `03_01_821049013_240p.ru.mp4`. Для 720p — `03_01_821049013_720p.ru.mp4`. Предпочтение пользователя из предыдущей работы — суффикс `.ru`, не `_RU`. Само имя НЕ задаёт основной язык аудио.

Полезное расширение: сохранение очереди между запусками и пропуск уже завершённых файлов. Это не означает продолжение кодирования незавершённого MP4 с произвольного места: сначала можно перезапускать только текущий незавершённый файл.

## 9. Синхронизация и контроль результата

- Никакого автоматического изменения темпа русской речи: её подгонка уже выполнена программой озвучки.
- Сохранять исходную временную привязку видео, русской дорожки и обоих SRT.
- Проверять стартовые смещения потоков и длительности. Не просто обнулять разные потоки независимо, теряя синхронность.
- Если русская озвучка короче видео и совпадает с концом RU SRT, разрешить сборку и сохранить весь конец видео; при копировании AAC не растягивать дорожку и не добавлять в неё звук.
- Не применять бездумно `-shortest`: короткий аудиофайл или субтитры не должны обрезать лекцию.
- Несовпадение озвучки с концом RU SRT и звук длиннее видео показывать как проблему для проверки; не маскировать их растяжением/обрезкой.
- Успех определяется кодом завершения FFmpeg И анализом итогового файла: читается, есть видео, две аудиодорожки и два субтитра, правильные языки, русский звук первый и основной, немецкий не основной.
- Проверить приблизительную полноту длительности и воспроизведение/декодирование образцов начала, середины и конца.
- Автоматический анализ структуры не заменяет проверку фактического языка/правильности входного аудио.

## 10. Первая версия и отложенные идеи

Первая версия:

1. Подбор комплектов вручную и по папке.
2. Очередь и ручное исправление подобранных файлов.
3. Режим копирования видеоряда и разрешения 240/360/480/720/1080p.
4. Русский звук первым и по умолчанию, немецкий вторым, два субтитра внутри MP4.
5. Аппаратное H.264-кодирование на M4.
6. Выбор папки результата, защита от перезаписи, прогресс и корректная остановка.
7. Короткий тестовый экспорт и проверка результата.

Отложенные/необязательные идеи:

- Отдельная дополнительная копия для Telegram только с русским звуком. После успешного теста двуязычного MP4 это запасной вариант, НЕ основной режим и НЕ причина убирать немецкий из требуемого файла.
- Сохранение очереди между запусками.
- Два параллельных задания после замеров.
- Выбор произвольного тестового фрагмента.
- CPU-профиль сжатия, расширенные параметры.

Не нужны на этом этапе: перевод, распознавание речи, синтез Siri, сканирование слайдов, AI-апскейл, автоматическая отправка в Telegram, создание MKV.

## 11. Проверенная команда FFmpeg — эталон

Команда успешно выполнена пользователем. Результат успешно проверен им на ПК и девушкой на двух Android. Использован FFmpeg, уже входящий в установленный Subtitle Edit:

`/Applications/Subtitle Edit.app/Contents/MacOS/ffmpeg`

```bash
cd "/path/to/lectures/Day_03" && \
"/Applications/Subtitle Edit.app/Contents/MacOS/ffmpeg" \
-hide_banner -n \
-i "03_01_821049013_720p.mp4" \
-i "03_01_821049013_720p.ru.siri.voice.wav" \
-i "03_01_821049013_720p.ru.srt" \
-i "03_01_821049013_720p.srt" \
-map 0:v:0 -map 1:a:0 -map 0:a:0 -map 2:s:0 -map 3:s:0 \
-map_metadata -1 -map_chapters -1 \
-c:v copy \
-c:a:0 aac -b:a:0 128k -ar:a:0 48000 -ac:a:0 2 \
-c:a:1 copy \
-c:s mov_text \
-metadata:s:a:0 language=rus \
-metadata:s:a:0 handler_name="Русский" \
-metadata:s:a:1 language=deu \
-metadata:s:a:1 handler_name="Deutsch — оригинал" \
-disposition:a:0 default \
-disposition:a:1 0 \
-metadata:s:s:0 language=rus \
-metadata:s:s:0 handler_name="Русские субтитры" \
-metadata:s:s:1 language=deu \
-metadata:s:s:1 handler_name="Deutsche Untertitel" \
-disposition:s:0 default \
-disposition:s:1 0 \
-t 30 -movflags +faststart \
"/path/to/output/Тест-RU-DE.mp4"
```

Не запускать её автоматически при простом чтении ТЗ. Выходной тестовый файл уже может существовать; `-n` запрещает перезапись.

Особенности эталона:

- `-t 30` ограничивает ТЕСТ, в полном экспорте этого ограничения быть не должно. При копировании видео длительность теста может немного отличаться из-за границ пакетов/кадров.
- Для длинной лекции дополнительно реализовать правила длительностей из раздела 9.
- Немецкий поток здесь уже AAC, поэтому `-c:a:1 copy` подходит. Для других источников сначала проверить кодек.
- В тесте исключены исходные главы и метаданные; сохранение глав для приложения отдельно не согласовано.
- Приложение должно передавать FFmpeg массив аргументов через Process, а не вставлять пользовательские пути в строку оболочки.

## 12. Фактические параметры тестовых файлов

Исходное видео:

- `03_01_821049013_720p.mp4`.
- Длительность 00:36:35.05.
- H.264 High, 1280×720, 25 кадров/с, 8-битный `yuv420p`, прогрессивное, BT.709.
- Немецкий звук AAC-LC, 48 кГц, стерео, около 189 кбит/с.

Русская озвучка:

- Длительность 00:36:34.49 — примерно на 0.56 секунды короче видео.
- WAV PCM 16 бит, 24 кГц, моно.
- В тесте перекодирована в AAC-LC 128 кбит/с, 48 кГц, стерео. Увеличение частоты/числа каналов не повышает качество исходной речи; эти параметры сохраняем как успешно проверенный профиль совместимости.

Итог теста по логу:

```text
Stream #0:0: Video: h264, 1280x720
Stream #0:1(rus): Audio: aac, 48000 Hz, stereo, 128 kb/s (default)
Stream #0:2(deu): Audio: aac, 48000 Hz, stereo, 189 kb/s
Stream #0:3(rus): Subtitle: mov_text (default)
Stream #0:4(deu): Subtitle: mov_text
```

Файл около 10 МиБ, обработка теста по логу заняла около 0.26 секунды с копированием видеоряда. Это НЕ замер скорости аппаратного перекодирования и не прогноз времени для целой лекции.

В текущем окружении уже проверено наличие в FFmpeg: `h264_videotoolbox`, `hevc_videotoolbox`, `libx264`, `aac`, `mov_text`. Отдельный `ffprobe` не найден ни в PATH, ни рядом с указанным FFmpeg. Это не доказывает его отсутствия на всём Mac; при разработке обеспечить подходящую зависимость. Для самостоятельного приложения не полагаться навсегда на установленный Subtitle Edit: предусмотреть проверяемый FFmpeg/FFprobe с учётом лицензии выбранной сборки.

## 13. Критерии приёмки

1. Папка с четырьмя комплектами, как в Day_03, автоматически даёт четыре корректных задания, а не дополнительные задания из отчётов/субтитров.
2. Пользователь может задать разное разрешение разным лекциям и запустить всю очередь без Терминала.
3. Итог — MP4 с нужными пятью потоками; русский аудиопоток первый и `default`.
4. Тестовый экспорт продолжает успешно воспроизводиться по-русски в Telegram на проверенных Android и ПК.
5. Исходники не изменены, молчаливой перезаписи результатов нет.
6. Нет обрезанного конца лекции из-за более короткого WAV; синхронизация проверена в нескольких местах.
7. Режим без перекодирования не перекодирует видеоряд; при уменьшении разрешения реально используется запрошенный режим, пропорции сохранены.
8. Ошибки/неоднозначности видны в очереди, незавершённые файлы не отмечаются успешными.
