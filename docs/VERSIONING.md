# Версии и неизменяемые выпуски

`main` хранит актуальные исходники. Тег `v2.0.0` фиксирует первый выпуск
из основной папки. `dist/v2.0.0` содержит проверенное приложение;
`releases/v2.0.0` — его ZIP, ZIP исходников, manifest и SHA256SUMS.

Актуальный выпуск — **2.0.2**; его приложение и архивы находятся в
`dist/v2.0.2` и `releases/v2.0.2`. Выпуски 2.0.0 и 2.0.1 сохранены.

## Следующая доработка

1. Проверить `git status`. Сохранить изменения пользователя.
2. Создать ветку для конкретной доработки, при необходимости отдельный worktree.
3. Изменить код и выполнить относящиеся к нему проверки. Для пробной сборки:
   `bash Scripts/build.sh --preview`. Старые приложения остаются на месте.
4. Назначить новую VERSION: 2.0.1 для исправления, 2.1.0 для новых функций,
   3.0.0 для несовместимых изменений. Увеличить BUILD_NUMBER. Обновить CHANGELOG.
5. Сделать коммит проверенного исходного кода. Выполнить `bash Scripts/build.sh`:
   появится новый `dist/vX.Y.Z`, существующий номер не перезаписывается.
6. Проверить новую сборку и записать результаты. Документацию можно закоммитить
   отдельно; изменения исходников после сборки потребуют свежей сборки.
7. На чистом рабочем дереве выполнить `python3 Scripts/release.py`.
   Скрипт сверяет VERSION, билд, хеши исходников, кодеки и подпись приложения,
   делает архивы, проверяет ZIP, создаёт новый аннотированный тег и атомарно
   публикует новый каталог в releases. Уже существующие каталог и тег — отказ.
8. Выполнить `python3 Scripts/verify-release.py vX.Y.Z`.
9. Предоставить пользователю новый выпуск. Рабочий ярлык не переключать скрытно.

Если сборка с выбранным номером уже существует, используйте `--preview`
для дальнейшей отладки или назначьте новый номер следующему выпуску.
Нельзя обходить отказ перезаписи удалением прежнего выпуска.

Git-теги не передвигать. При сбое между созданием тега и публикацией каталога
скрипт консервативно сохранит тег; проверить состояние вручную, не удалять его
автоматически и не создавать другой архив под тем же именем.

## Откат

Распакуйте приложение из нужного старого ZIP в отдельную папку. Для просмотра
исходников можно создать отдельный worktree от тега. Разрушительный `reset`
основной рабочей папки для этого не нужен.

В папке отдельного выпуска контрольные суммы проверяются так:

```bash
shasum -a 256 -c SHA256SUMS
```

Git хранит историю исходников; игнорируемые ZIP и `.app` хранит файловая система.
Резервная копия на том же диске не заменяет Time Machine/внешний диск.
Публикация в GitHub выполняется только по отдельному запросу владельца.
